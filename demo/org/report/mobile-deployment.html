手机端部署与现场演示方案

为项目申报现场考察，复现 MobileIE 官方手机测试流程，并补充可展示的增强效果。
创建：2026-11-08 状态：启动 作者：claude code (local)
结论先行：论文的手机部分只测推理速度（Snapdragon 8 Gen 3，0.895 ms），仓库没有手机 App 或可视化 demo。因此采用 B 方案：手机用 AI Benchmark 实测延迟，电脑复用官方 test_TFLite_RGB.py 生成前后对比图，现场组合展示——不新写安卓 App。

1. 任务与边界

导师在 2026-11-08 的会议中要求：尽快在安卓手机上把论文里的 AI Benchmark 跑起来并演示，用于项目申报的现场考察，“不用做研究，原文怎么弄就怎么弄”。

问题核对结果
论文手机部分做了什么？只在 Snapdragon 8 Gen 3 上测延迟（0.895 ms / 1100 FPS），用于复杂度对比。
官方 README 的手机流程？lolv1.tflite → 导入 AI Benchmark → 获取推理速度。
仓库有手机 App 吗？没有。只有 Python 训练、测试与 TFLite 转换脚本。
论文效果图来自手机吗？不是。效果图来自数据集 + GPU 推理。
目标冲突：“直接复现论文手机做法”只能得到延迟；“现场看到增强效果”论文并未提供手机端方案。两者需要用同一份模型、两条路径拼起来。

为什么不用现成 App 看效果

  • AI Benchmark：Custom Model 只输出延迟与错误日志，没有图像预览。
  • Google AI Edge Gallery：支持侧载模型，但内置任务只有分类/检测/LLM，不支持任意图生图。
  • ML Bench：偏分类/检测，需要标签与元数据。
  • TensorFlow 官方 Android 示例：都是写死模型的参考实现，换模型需改代码并重新编译。

3. 模型事实（已解析）

项值
文件MobileIE/pretrain/lolv1.tflite
大小23 KB
输入serving_default_input_1:0，固定 1×400×600×3，FLOAT32
输出StatefulPartitionedCall:0，1×400×600×3，FLOAT32
算子23 个标准算子：CONV_2D ×6、MUL ×9、ADD ×2、LOGISTIC ×2、PAD / MEAN / PRELU / REDUCE_MAX 各 1
自定义算子无
单输入、单输出、固定 4D 形状、无自定义 op，满足 AI Benchmark Custom Model 的加载条件。输入固定为 400×600，手机照片必须先缩放/裁剪。

4. 已跑通的效果与数值（2026-11-08）

验证通过：用官方 test_TFLite_RGB.py 跑完 LOLv1 eval15 全部 15 张，PSNR 均值 23.619 dB，与论文报告的 23.62 dB 一致。

左：输入暗光图（已缩放到 600×400）；右：MobileIE 增强结果。完整对比见 results/compare_sample/ 与 results/compare_lol_eval15/。

环境说明 本机 TensorFlow 2.20/2.21 原生库初始化失败，电脑侧改用官方 LiteRT 运行时 ai-edge-litert 提供 tf.lite.Interpreter 兼容层（关闭默认 XNNPACK delegate，避免崩溃）；官方脚本的预处理/推理/保存逻辑未改动。手机端仍使用原始 .tflite 模型。

5. 手机端操作要点

  1. 官网下载 AI Benchmark（v7.0.0，Android 5.0+，APK 约 1.4 GB），授予存储权限。
  2. 把 lolv1.tflite 复制到手机 Download，命名为 model.tflite。
  3. 先完整跑一次标准测试，再进入 PRO Mode → Custom Model。
  4. 选择模型（自动读取 Download，或文件管理器手动选，需开启“显示内部存储”）。
  5. 精度选 FP32；后端依次尝试 CPU/XNNPACK、NNAPI、GPU（以及机型对应的 QNN/Neuron/ENN）。
  6. 记录延迟并截屏/录屏；提前准备离线备份，现场不依赖网络。

注意 AI Benchmark 是跑分工具，不是模拟器；自定义模型模式不显示增强后的图像。

7. 现场演示串场（草案）

  1. 背景：MobileIE 是 ICCV 2025 的 4K 参数极轻量图像增强网络，面向手机端实时推理。
  2. 测速：在手机上用 AI Benchmark 加载官方 TFLite 模型，展示后端加速下的延迟/吞吐。
  3. 效果：展示同一模型对暗光照片的增强前后对比（左原图、右增强，输入 400×600）。
  4. 收尾：强调“4K 参数 + 手机端实时 + 无需联网”，对应项目申报的端侧智能主题。
  5. Q&A 预案：为什么不做实时 App？——论文原始流程只做端侧测速；延迟差异？——机型/后端/温度不同；效果是否手机算的？——效果由官方 TFLite 脚本输出，模型完全一致。

8. 风险与备选

风险应对
现场要求手机摄像头实时增强B 方案不满足；备选 Termux 跑官方脚本（0.5–1 天）或最小安卓 App（约 1 天）
模型输入固定 400×600手机照片先用 prepare_demo_images.py 缩放/裁剪
虚拟环境缺少 TensorFlow新建独立演示环境，避免影响研究环境
AI Benchmark 下载/版本差异官网直连 APK；提前安装并完成标准测试；必要时用 Nightly
模型只擅长低光现场素材选暗光照片；水下增强需另行转换
