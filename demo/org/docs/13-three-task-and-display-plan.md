## 本次确认的范围

1. **三种任务**：低光增强、水下增强、RAW→RGB ISP。以[论文 §2.1/§4](https://openaccess.thecvf.com/content/ICCV2025/papers/Yan_MobileIE_An_Extremely_Lightweight_and_Effective_ConvNet_for_Real-Time_Image_ICCV_2025_paper.pdf)与官方代码为准；会议中的“超分/四项”属于需核正的口头表述。
2. **不增加参数面板**：逐任务核查原生推理签名。LLE/UIE 的 `MobileIELLENetS.forward(x)` 与 ISP 的 `MobileIEISPNetS.forward(x)` 均仅接受图像张量；权重是已训练参数。导出后继续核验实际输入列表。禁止用可调曝光、Gamma 或输出混合代替模型原生参数；固定 baseline 的内部常量不变成用户面板。
3. **两种展示**，独立于三种任务选择：动态在同屏显示“原图↔baseline”和“原图↔MobileIE”两组窗口，滑动分界同步；静态保留三图总览。电脑优先横向并列，手机按可用空间安排两组窗口，保持同图坐标与比例。
4. **明确本次任务**：展示上方显示本次实际处理任务；标题与处理记录绑定，切换任务清除旧输出，避免把已选任务误当旧图任务。导出图及 JSON 同样标注。
5. Android 与既有 Python 桌面版接续实现。0.1.2 真机复验已通过，见[12](12-android-0.1.2-reverify.md)；保留旧安装包和证据。早期 Windows 不作独立验收项的决定保留历史，新会议要求电脑先演示，因此要检查实际桌面展示链路，无需另建 Windows 原生开发环境。

## 模型和输入

| 任务 | 已有官方权重 | 输入与实施要点 |
| --- | --- | --- |
| 低光增强 | `lolv1.tflite` | 保留已验收模型字节，RGB 600×400；固定 Gamma baseline |
| 水下增强 | `uieb_best_slim.pkl` | 官方 RGB 网络，导出移动模型并对照 PyTorch；使用水下样例与明确的传统颜色校正 baseline |
| RAW→RGB ISP | `zrr_best_slim.pkl` | 四通道 packed RGGB RAW，PixelShuffle 后输出 RGB；独立输入/模型链路，不把普通 JPEG 冒充 RAW |

ISP 输入格式和有效样例先验收。普通系统拍照返回 JPEG，不能当作传感器 RAW；界面须明确可用输入。任务切换必须真正切换权重、输入校验、样例及 baseline，并记录各模型摘要；不能只切换标签。
