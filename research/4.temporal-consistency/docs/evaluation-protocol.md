# 评价协议（草案）

- 创建：2026-11-05 · claude code (local)
- 状态：**草案，待与导师确认**。确认后再固化为正式评价标准。

## 1. 要回答的问题

1. 闪烁降低了多少？——时序指标；
2. 画质有没有变差？——保真度指标；
3. 代价是多少？——参数量、MACs、延迟、内存；
4. 在什么条件下会失效？——快速运动、遮挡/视差、自动曝光、低光噪声强度。

所有对比必须共享**同一段输入视频、同一退化随机种子、同一分辨率与帧率**。

## 2. 数据集

### 2.1 合成受控视频（主实验）

沿用 3 号工作的构造：静态大图 + 匀速平移裁剪 + 低光退化。

| 项 | 设置 |
| --- | --- |
| 场景 | 至少 8–10 张不同内容的大图（室内/室外/夜景/纹理丰富/平坦天空） |
| 分辨率 | 640×480，30 FPS，60–120 帧 |
| 运动 | 速度扫描：2 / 4 / 8 / 16 / 32 px/帧（覆盖慢速到快速） |
| 退化 | `(x/255)^2.2 × 0.35` + 泊松噪声（40 光子）+ 读出噪声（σ=0.008）+ 逐帧 JPEG 70 |
| 变体 | 单独开关 noise / JPEG / exposure（±3%），用于来源拆解 |
| 划分 | 场景级划分，训练/验证/测试不共享同一张大图 |

优点：运动已知，可用精确平移对齐；缺点：无遮挡、无视差、无真实传感器噪声。

### 2.2 真实视频（泛化验证）

| 来源 | 说明 | 状态 |
| --- | --- | --- |
| 自拍手机夜景 | 固定曝光 / 自动曝光两组；手持平移、行走、静止；1080p 下采样到 640×480 | 待用户提供 |
| SDSD | 静态/动态场景低光视频，有 GT | 待确认许可与下载 |

真实视频没有 GT 时，画质用无参考指标（NIQE/BRISQUE）或人工偏好，仅作辅助。

## 3. 指标

### 3.1 时序一致性（越低越好）

**A. 已知运动对齐残差**（合成视频）：

```text
D_t = mean_p | Warp(O_{t-1})[p] - O_t[p] |      # 0–255 灰度级
Flicker = mean_t D_t
Amplification = Flicker_output / Flicker_input
```

**B. 光流对齐残差**（真实视频）：

```text
用 Farneback 光流把 O_{t-1} warp 到 O_t，再计算平均绝对差
```

**C. 逐像素时间标准差**（对齐到同一视角后）：

```text
sigma(p) = std_t O_t(p)
TemporalStd = mean_p sigma(p)
```

**D. JND 超限比例**（启发式，2/4/8/16/32 灰度级）：

```text
Exceed(th) = fraction of pixels with aligned diff > th
```

**E. 时间频谱**（对齐后逐像素 PSD 的平均）：

```text
BandPower(>3Hz) / BandPower(>0Hz)
```

随机逐帧噪声应表现为宽带（高频占比高）；慢速亮度脉动表现为低频集中。

**F. 亮度漂移**：

```text
DriftStd = std_t( mean(O_t) - mean(GT_t) )
```

### 3.2 画质（越接近 GT 越好）

- PSNR、SSIM（与 2 号工作同口径：RGB 高斯窗 SSIM）；
- 可选 LPIPS（若环境允许）；
- 真实无 GT 视频：NIQE/BRISQUE + 人工偏好（至少 2 人，盲评）。

### 3.3 效率

| 指标 | 口径 |
| --- | --- |
| 参数量 | 推理态 slim 网络 |
| MACs | 400×600 输入，thop |
| GPU 延迟 | RTX 5060 Laptop / 服务器 A100，batch=1，warmup 50 次，取中位数 |
| 手机延迟 | TFLite / Android 模拟器，400×600，报告 FPS 与单帧延迟 |
| 内存 | 推理峰值显存/内存 |
| 额外延迟 | 是否引入帧缓冲（recurrent/双向） |

## 5. 报告规范

- 每个场景单独报告，再给 mean ± std；不只报最好的场景；
- 所有方法使用同一随机种子与同一输入序列；
- 闪烁-画质权衡用曲线展示（横轴闪烁，纵轴 PSNR/SSIM），并标注 α/超参；
- 效率表必须同时给参数量、MACs、延迟；不能只报 FPS；
- 视频材料：输入 | 输出 | GT 三联对比 + 帧差放大 20×；
- 明确标注合成 vs 真实、是否已知运动。

## 6. 成功判据（草案，待导师确认）

建议把“解决”定义为同时满足：

| 维度 | 建议阈值 |
| --- | --- |
| 闪烁 | 对齐残差 / 时间标准差相对基线降低 **≥50%** |
| 画质 | PSNR 下降 **≤0.1 dB**，SSIM 下降 **≤0.005** |
| 参数 | 相对 4,075 增加 **≤10%** |
| 延迟 | GPU 400×600 增加 **≤10%**（或 ≤2 ms）；手机 ≥30 FPS |
| 延迟帧 | 不引入超过 1 帧的缓冲（若采用 recurrent） |
| 快速运动 | 16 px/帧下闪烁仍降低 **≥30%**，无明显拖影 |
| 泛化 | 真实视频上相对 EMA/光流 EMA 不劣，且在快速运动/遮挡场景更优 |

> 这些阈值是为了让后续实验有明确目标，不是最终结论；导师确认后再调整。

## 7. 已知风险

1. **后处理足够强**：光流 EMA 在慢速平移下已降 73%。若训练期方案不能证明快速运动/延迟优势，需重新定位（例如“轻量后处理 + 训练约束”的组合）。
2. **真实视频无 GT**：画质评估只能无参考，需人工盲评补充。
3. **合成到真实的差距**：合成运动无遮挡/视差，可能高估方法效果；真实视频必须单独报告。
4. **指标口径不统一**：不同论文的“temporal consistency”定义不同，比较时需注明公式与单位（0–255 vs 0–1）。
