## 1. 研究目标与证据要求

研究问题：在移动端计算与状态内存预算内，如何联合建模视频中的增强映射、噪声和帧间对应关系，改善画质、时间稳定性与细节保持之间的权衡？

论文需要建立三条证据链：

1. 原模型的具体设计为何在视频条件下受限：机制推导、受控干预和跨场景结果相互支持。
2. 新设计如何解决这一限制：区别于已有方法，且不能被等预算增宽、常规去噪或简单时域平滑解释。
3. 在合理预算下获得实质收益：报告画质、短/长期稳定性、运动细节、处理延迟、状态内存，并有真实视频验证。

结构修改的规模不等于创新程度。已有时序损失应保留为必要基线；是否采用新的时序结构由实验决定。4K 参数与零额外开销作为原模型参照，不再预先排除具有合理收益的结构重设计。

## 2. 从代码还原原模型

代码锚点：`MobileIE/model/lle.py`、`MobileIE/model/utils.py`、`MobileIE/model/utils_IWO.py`。

推理态主要信息流，`B×3×H×W` 输入、默认隐藏通道 `C=12`：

```text
x → [Conv5×5 → PReLU → Conv3×3] → FST → Conv3×3 → FST → f
g = sigmoid(Conv1×1(GAP(f)))                         # B×C×1×1
m = max_channel(g ⊙ f)                              # B×1×H×W
l = sigmoid(Conv1×1(m))                             # B×C×H×W
y = Conv3×3(l ⊙ g ⊙ f)                             # B×3×H×W
```

这是逐帧映射 `y_t=f_theta(x_t)`，没有历史状态或显式运动建模。全局注意力提供全图依赖，不能把整个网络的感受野简单描述为几个局部卷积的范围。

### 2.1 MBRConv：训练参数化与推理算子分离

训练时使用不同卷积核及其 BN 分支，拼接后用 1×1 卷积压缩。部署时，在 BN 使用固定统计量的 eval 条件下，将 BN、卷积核填充和线性压缩合并为单个卷积。

- 它增加训练时的参数化能力，部署后仍是空间卷积。
- 不能把训练时的多分支直接解释为视频的多帧信息。
- 需要在已训练权重上验证重参数化等价；随机初始化网络的检查不能替代这一检查。
- 合并多条具有相同时间支持的线性分支，可以减少算子；不能一般性地把依赖历史帧的算子精确折叠成只接收当前帧的二维卷积。

### 2.2 FST：视频噪声敏感性的机制假设

代码实际计算 `u=block1(x)`，再得到 `z=a*u²+b`，其中 `a=weight1*weight2` 是共享标量，`b` 是逐通道偏置。它不是原输入与变换特征之间的残差相加。

对特征扰动 `delta`，精确差为：

```text
FST(u+delta)-FST(u) = 2*a*u*delta + a*delta²
```

因此，局部响应幅度会调制噪声增益，二阶项也可能引入偏置。这是结构分析得到的候选机制，尚不能据此断言 FST 是整网闪烁主因：前后层缩放、训练后的权重及注意力都可能改变最终敏感性。

诊断应测量固定场景、多次独立噪声下各层的均值偏移、方差及输入扰动响应，比较相近亮度与画质下的变化；并干预 FST、注意力和整网特征，而非只比较最终一个残差数字。

### 2.3 HDPA：全局和局部稳定性需分别研究

全局分支每帧独立池化，可能随构图、曝光或噪声变化；局部分支包含通道最大值，可能因不同通道竞争而切换。两者与特征乘法的共同作用需要独立测量。

冻结全局注意力只检验一种推理期干预。它不等于训练期移除注意力，也不足以排除全局分支的作用。所有干预必须使用完全相同的退化帧。

## 3. 原训练流程与当前缺口

### 3.1 warm-up

`main.py` 使用 `forward_warm` 对遮挡输入训练两个输出头：一个趋向正常曝光 GT，另一个重建原始低光输入。warm-up 默认 10 轮、学习率 1e-6，之后重新建立主训练优化器。

这一阶段主要经过 head/body 和两个输出头；主训练的注意力路径不在该 warm-up 前向链路中。需要核实其学到的特征如何迁移到视频任务，而不是将其直接称为时序预训练。

### 3.2 主训练与任务损失

`LossLLE` 包含残差加权绝对误差、裁剪输出上的颜色余弦项和 PSNR 相关项。代码中的 `OutlierAwareLoss` 按每图每通道的空间残差统计计算权重，不能未经公式核对就解释为滑窗局部方差。

上游配置默认 Adam、主学习率 1e-3、2000 轮；调度器为 `CosineAnnealingWarmRestarts(50,2,1e-7)`。需要保留具体实现，不能仅以“每50轮重置”概括倍增的重启周期。

当前独立消融入口默认256裁剪，上游数据类直接读入整图；两者需标明不同协议。官方验证代码先计算逐通道 MSE 再平均对数 PSNR，与先聚合 RGB MSE 的常见定义有差别。训练选模指标与最终论文指标应分别明确。

### 3.3 IWO 与 warm-up 是不同机制

原论文补充分析描述使用前1000轮得到的权重作为先验继续优化。仓库提供 `utils_IWO.py`，但 `lle.py` 导入的是普通 `utils.py`，主训练入口没有阶段切换与先验权重加载逻辑。

仅实例化 IWO 类不构成 IWO 复现：其冻结权重和增量参数需要正确初始化。必须核对载入键、增量初始化、BN统计、优化器/调度器状态和后续轮数，记录与普通继续训练的差别。

另一个需澄清的问题：若 `W=W_pre+delta_W`，且增量不受约束，仅这一加法参数化并不自动带来新的函数能力。收益可能来自初始化、正则或优化器重置等，需要相应控制组。上述为优化层面的分析，不能代替原论文的实验核查。

参考：[MobileIE 原论文及补充分析](https://arxiv.org/html/2507.01838v1)。

## 4. 结构研究候选

这些方向是实验假设，尚未确认新颖性。首先对照原文和代码，避免把常规 recurrent、Retinex 或 feature EMA 重新命名为贡献。

| 方向 | 对原模型的实质改变 | 必须回答的问题 | 主要风险 |
| --- | --- | --- | --- |
| 时序增强映射与细节恢复分开建模 | 将缓慢变化的曝光/颜色控制与快速变化的局部细节分开，给控制量显式历史状态 | 能否稳定映射，同时响应真实光照变化和场景切换？ | Retinex/时序分解已有工作多，需验证独特机制 |
| 重设计特征变换与不确定性传播 | 从平方特征的噪声传播出发，研究有界响应或可靠性调制的时序特征变换 | 是否在保留纹理的同时抑制随机噪声，而不只是降低增益或模糊？ | 普通去噪、激活替换就可能解释收益 |
| 因果时空骨干与有限状态 | 重设计 MBR 的时间支持和特征更新，在训练/推理中都显式使用历史 | 与同宽多帧拼接、feature EMA、简单 recurrent 相比有何优势？ | 对齐开销、遮挡、状态漂移和部署算子限制 |

可从少量候选中选择，而不是同时堆叠三条路线。任何历史状态都应有置信度与重置机制的对照；后者是否有效也要通过遮挡、曝光突变和场景切换验证。

## 5. 对照体系

| 类别 | 必要或候选方法 | 目的 |
| --- | --- | --- |
| 原始模型 | 官方预训练 MobileIE；同协议重训 MobileIE | 区分复现差距与方法收益 |
| 训练控制 | 普通单帧去噪增强训练；相同增广；普通时序损失 | 区分去噪、数据和新设计的贡献 |
| 简单后处理 | 输出 EMA、运动补偿 EMA，扫描平滑强度 | 判断简单滤波能达到的画质—稳定性权衡 |
| 传统去噪/增强 | BM3D/NLM 或双边滤波配合固定增强；VBM3D配合相同增强器 | 分开检验单帧去噪与多帧冗余收益 |
| 学习型后处理 | Deep Video Prior；选择可复现的盲视频一致性方法 | 与通用去闪烁思路对照 |
| 视频增强 | StableLLVE；FastLLVE；按资源和可复现性筛选较新方法 | 对照相同任务的已有视频建模 |
| 等预算结构 | 单帧增宽、两帧拼接、feature EMA、小型 recurrent | 排除额外参数、历史输入或常见状态更新的解释 |
| 分析参照 | 合成数据的真值运动补偿/已知噪声条件 | 区分模型瓶颈与光流/噪声估计误差；不得与可部署方法混排名 |

传统方法不是每种都跑：先选一个有竞争力的单帧去噪对照、一个利用跨帧冗余的方法。VBM3D的标准噪声假设与当前泊松+JPEG退化不同，必须说明噪声估计/适配方法，避免不公平地用失配参数削弱对照。

主要来源：

- [StableLLVE，CVPR 2021](https://openaccess.thecvf.com/content/CVPR2021/papers/Zhang_Learning_Temporal_Consistency_for_Low_Light_Video_Enhancement_From_Single_CVPR_2021_paper.pdf)：直接相关的单图训练与低光视频一致性工作，必须深入比较。
- [FastLLVE](https://arxiv.org/abs/2308.06749)：实时视频增强与亮度一致性相关对照。
- [Deep Video Prior](https://arxiv.org/abs/2010.11838)：视频特定优化成本应单独报告。
- [VBM3D实现与变体，IPOL](https://www.ipol.im/pub/art/2021/340/)：传统跨帧去噪对照与可复现实现。
- [RetinexMCNet，ICCV 2025](https://openaccess.thecvf.com/content/ICCV2025/papers/Wang_RetinexMCNet_A_Memory_Controller_Dominated_Network_for_Low-Light_Video_Enhancement_ICCV_2025_paper.pdf)：分解与历史状态相关，作为结构设计的重复风险核查对象；具体复现范围待全文和代码核查。

## 6. 指标与公平比较

- 画质：统一 RGB/Y、裁剪、clamp、窗口和动态范围定义的 PSNR/SSIM，必要时补感知指标。
- 稳定性：有效区域中的运动对齐残差、相对 GT 时间变化的误差、短/长期漂移。真实视频用共同的运动估计与遮挡规则，避免每种方法自行选择最有利光流。
- 细节与运动：边缘/纹理保持，快速运动、遮挡、曝光突变、场景切换的专项结果；同时观察拖影和响应滞后。
- 效率：相同分辨率/设备下的整条推理流程，包括运动估计、预处理、状态更新；报告单帧处理时间、吞吐、未来帧等待、状态内存及模型参数。
- 数据：场景级划分；训练、调参、测试分离；合成和真实视频分别报告；共享同一退化实现和随机输入。
- 统计：逐序列结果及多 seed 分布，不将同一视频的相邻帧视作独立样本来夸大统计证据。

因果 EMA 使用历史不代表必须等待未来帧；计算开销、历史缓冲和滤波响应滞后应分开描述。在线因果方法与离线双向方法应分别比较。

既有的“降50%/PSNR降不超0.1dB”等只能作为内部候选目标。当前基线尚待修正，正式阈值应在可信基线和数据集确定后固定。论文应展示优于强对照的 Pareto 改善，而不是只达到相对原模型的单一阈值。

## 7. 执行顺序与阶段产出

1. 完成原模型核查表：结构/张量形状/参数与MACs、warm-up、IWO、损失、训练与选模口径；分开标注论文描述、代码事实、缺口。
2. 修正评价中的平移回卷、光流方向、差分溢出及有损缓存；保留旧结果，在新实验身份下验证运动与指标。
3. 用固定数据验证机制：噪声强度、曝光、构图、运动分别干预；测试 FST 与 HDPA 的响应，并补匹配画质的去噪对照。
4. 在可信协议下做训练/结构候选试验，先得到方法增益与失效案例，再决定正式结构及大规模消融矩阵。
5. 完整训练、跨场景/真实视频与效率评估，补等预算控制和与已有工作的差异分析，形成可写入论文的结论。
