# R24 冻结网络的当前全局通道门控干预

创建：2026-11-11T23:09:00+08:00；作者：Codex  (sqs_A100)；原因：R23实际历史的全局RGB误差项值得追踪，但误差分解未因果定位；用一个有界节点干预检验，而非扩大模块训练网格。

冻结R21四模式×双seed4000全部8权重，四native开发缓存全部16帧，noreset/raw，32权重/片段组合。三输出为current替代、原causal、current-global-gate causal，共96逻辑行，其中前64为同CPU正式结果严格回放，新增32干预输出；不按片段、seed或PSNR选模型。

原MobileIE的att为GAP(body)→1×1 conv→sigmoid，输出1×12×1×1全局通道门控。先用同一已训练网络的当前输入获得g_cur，再将真实历史调用的att输出替换为g_cur；head/body特征、权重及空间att1公式不改。att1接收不同全局门控后数值允许改变，这是该节点下游作用，不能假称空间门控值被固定。post模式两个共享映射分支都用g_cur，当前分支本来相同，历史分支改变。

只用当前低光输入及既有teacher flow/mask，g_cur不接触GT。GT仅用于原评价和全帧RGB误差分解。逐frame原causal/干预的body输出必须逐像素相同，记录640组body hash/等值验证；current分支post重复门控亦应一致。首帧历史替代不应改变输出（预设<=1e-4灰度级）；64序列/1024帧的正式CPU指标回放最大差<=1e-10；MSE分解1e-12、PSNR一致1e-8dB。失败保留，不放宽门槛。

CPU FP32/batch1、Torch2/OpenCV1，零训练、不读取新测试素材。保存全部96序列/1536帧质量、GT估计flow时序指标、全局/中心化MSE、gate向量与body验证。完整对比32干预对原causal/current及同CPU R20 postwarp.5强参考。逐片/双seed全报，不把全局MSE均值和平均PSNR排名混同。

该探针只检验一个内部读出节点是否介导变化，不等于新视频模型或训练方案。对pre模式获得当前gate需要额外当前映射，post可复用已有当前分支，但都不能据此声称优于单前向+缓存输出后处理的效率。实验共享计算不当部署成本；无效则降低该假设优先级，有效也需原结构适配/预算与文献强控制，而非直接称创新。GT估计对应上限留作后续必要时的另一诊断。
