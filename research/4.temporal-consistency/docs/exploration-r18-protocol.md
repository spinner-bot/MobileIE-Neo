# R18 监督配对与几何误差诊断（不改现有评价）

创建：2026-11-11T21:10:24.111510+08:00；作者：Codex  (sqs_A100)；原因：R16时域贡献仍小，固定原生图的部分边缘位置差异值得核验，先检查标签而非继续堆模型。

已有R4 mapping是光度标定，不等于空间配对核验。本轮仅CPU使用原12训练和4原生dev，未读任何保留测试。12训练片各frame0/8/15同一ROI x704:1216,y396:684，共36；4原生dev每片全部16，共64；合计100原始input/GT诊断。另在4dev/frame8复用R16预登记图的R14 native plain seed0输出，4项预测/GT诊断，共104项。所有固定项保留，不能据结果更换片或丢弃不利样本。

定义：RGB转灰，Gaussian sigma1，Sobel3有符号x/y组成两通道，float32；对GT中心margin48的模板，在输入裁去16边界的区域做TM_CCOEFF_NORMED，搜索dx/dy各[-32,32]整数。零偏移为score[32,32]，正dx/dy表示在input的GT坐标+(dx,dy)采样；无循环、无wrap。记录最优/零NCC、排除最优Chebyshev半径3后次峰、峰差、边界命中和梯度能量。GT/input近常量梯度std<1e-7则记degenerate，不以OpenCV常量模板的1当成功。peak≥.3、gap≥.01且不在边界仅作为诊断标记，所有行照报，不当真实配准精度或数据质量真值。

4个模型输出额外记共同margin48内原始与GT拟合平移后的PSNR变化。这是使用GT的oracle诊断，禁止作为可部署方法/新主指标/论文性能提升，禁止替换R1–R16既有评价。输入结构/光度/噪声会影响估计，整数平移不覆盖视差/局部动态/亚像素误差；失败或近零结果也完整保留。

CPU fixture先验证已知无wrap平移方向及正仿射亮度变化、不偏移同图和常量退化；再正式跑104项。源PNG384 SHA与R10 cache SHA、旧显示数组SHA、所有地图/逐片统计/过程均保留。图固定4dev/frame8，显示NCC搜索面与纵向边缘profile，不挑最大误差案例。若出现大位移，只能形成标签配对假设，下一步需分离摄像机/帧同步/局部结构，不能直接指责数据错误或改GT。

方法依据：[OpenCV模板匹配公式与多通道定义](https://docs.opencv.org/4.13.0/df/dfb/group__imgproc__object.html)。调研中BVI原论文指出监督配对同步重要，但不证明OLiVES存在相同问题，需本轮独立核验。
