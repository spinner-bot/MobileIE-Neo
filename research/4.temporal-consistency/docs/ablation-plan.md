# 逐模块消融方案（控制变量）

- 创建：2026-11-05 · claude code (local)
- 目的：回答“MobileIE 的哪个模块在放大帧间闪烁”，为方法设计提供依据；同时满足导师“逐模块搞懂模型”的要求。
- 前置：3 号工作只做了**冻结**全局注意力（推理期缓存首帧输出），不是训练期消融；本方案要求每个变体**重新训练**。

## 1. 模型结构回顾（推理态 `MobileIELLENetS`）

```text
x0 = head(x)                 # MBRConv5 + PReLU + MBRConv3，FST 融合
x1 = body(x0)                # MBRConv3，FST 融合
x2 = att(x1)                 # 全局通道注意力：AdaptiveAvgPool -> Conv1x1 -> Sigmoid
m  = max(x2 * x1, dim=1)     # 通道维最大响应
x3 = att1(m)                 # 局部注意力：Conv1x1(1->C) -> Sigmoid
x4 = (x3 * x2) * x1          # 两路注意力调制
out = tail(x4)               # Conv3x3 -> 3 通道
```

训练态 `MobileIELLENet` 的结构相同，只是 MBRConv 为多分支、FST 含可学习标量/偏置，`slim()` 负责重参数化。

## 2. 变体矩阵

| ID | 变体 | 实现方式 | 想验证的假设 |
| --- | --- | --- | --- |
| V0 | Full | 原模型 | 基线 |
| V1 | w/o 全局注意力 | `x2 = 1`（移除 `att` 分支） | 全局池化是否引入亮度/通道抖动 |
| V2 | w/o 局部注意力 | `x3 = 1`（移除 `att1` 分支） | 局部响应是否放大高频噪声 |
| V3 | w/o 双注意力 | `x4 = x1` | 注意力整体对闪烁的贡献 |
| V4 | w/o FST 融合 | `FST.forward` 退化为 `block1(x)`，去掉 `w1*x ⊙ w2*x + bias` | 二次融合是否放大噪声 |
| V5 | w/o MBR 多分支 | 训练态直接用单分支 `Conv2d`（5×5/3×3/1×1） | “多分支训练 + 重参数化”是否影响噪声敏感性 |
| V6 | w/o warm-up | 跳过 warm-up 阶段，直接主训练 | IWO/warm-up 是否让网络更依赖噪声细节 |
| V7 | 冻结全局注意力（推理） | 3 号已有；作为参考，不需重训 | 与 V1 对照，区分“冻结”与“移除” |

> 说明：V1/V2/V3 是训练期移除，不是推理期冻结；V7 只用于解释 3 号结果，不作为方法变体。

## 3. 训练协议

| 项 | 设置 |
| --- | --- |
| 数据 | LOLv1 `our485`（485 对），验证 `eval15` |
| 分辨率 | 256×256 训练，400×600 / 640×480 评测 |
| 优化器 | Adam，lr 1e-3，warm-up lr 1e-6，CosineAnnealingWarmRestarts(50,2,1e-7) |
| Batch | 4（8×A100 可加大到 16，需同步调整 lr） |
| Epoch | 阶段一 400（快速排序）；阶段二 2000（与官方配置一致，用于最终表） |
| 种子 | 至少 2 个种子，报告 mean ± std |
| 权重保存 | 每个变体保存 `model_best.pkl` 与 `model_best_slim.pkl` |
| 一致性检查 | 每个变体的 `slim()` 输出与多分支输出最大差 < 1e-5 |

**重要**：所有变体必须在**同一训练预算、同一数据顺序、同一随机种子集合**下比较；不能“V1 训 400、V0 训 2000”。

## 4. 评测协议

每个变体在以下三项上评测：

1. **画质**：LOLv1 eval15 的 PSNR / SSIM（15 张，CPU/GPU 均可）；
2. **闪烁**：3 号工作的合成真实退化视频（60 帧，640×480，固定种子），报告：
   - 对齐帧差均值、放大倍数；
   - 逐像素时间标准差；
   - >8/255、>16/255 像素比例；
   - 时间频谱 >3 Hz 功率占比；
3. **效率**：slim 参数量、MACs（400×600）、GPU 延迟。

## 5. 预期与解读

| 观察 | 可能结论 | 对方法的启示 |
| --- | --- | --- |
| V1 闪烁显著下降、画质不变 | 全局注意力是抖动源 | 训练期约束全局注意力，或改造成时序稳定版本 |
| V2 闪烁下降 | 局部注意力放大高频噪声 | 局部注意力需要时域平滑/正则 |
| V4 闪烁下降 | FST 二次融合放大噪声 | 在融合处加时序约束 |
| V5 闪烁下降 | 多分支训练导致噪声敏感 | 重新设计训练策略，保留重参数化 |
| V6 闪烁下降 | warm-up 让网络学噪声 | 调整 warm-up 目标/数据增强 |
| 所有变体都下降有限 | 闪烁来自卷积特征本身的逐帧随机性 | 需要显式时序损失/帧间信息，而非只改结构 |

注意：消融变体可能同时降低画质；必须看“闪烁-画质”联合结果，不能只看闪烁。

## 6. 实现要点

1. **不改上游默认行为**：在 `research/4.temporal-consistency/scripts/model_variants.py` 中定义子类/工厂，通过 `variant` 参数选择；`MobileIE/` 保持上游 + 已标注的 local change。
2. 变体需要同时支持训练态（多分支）与推理态（slim）：
   - V1–V4 只改 `forward` / FST 融合，重参数化逻辑不变；
   - V5 需要单独的“单分支训练态”定义，`slim()` 直接返回自身卷积权重；
3. 训练入口复用 `MobileIE/data/lledata.py`、`MobileIE/loss.py`、`MobileIE/option.py` 的数据加载与损失，写一个精简的 `train_ablation.py`，避免复制整个 `main.py`；
4. 训练日志与权重放 `research/4.temporal-consistency/results/ablation/<variant>/`，不入库大文件；
5. 每个变体训练前跑一次 `slim()` 等价性检查，防止重参数化实现错误污染结论。

## 7. 依赖与排期

- 服务器：2026-11-07 起 8×A100 40GB；
- 先做阶段一（400 epochs × 7 变体 × 2 seeds），约 1 周内出排序；
- 再对 V0 + 前 2–3 个关键变体做 2000 epochs 正式训练；
- 消融结果直接用于 P2 的方法选型（改哪里、加什么时序约束）。
