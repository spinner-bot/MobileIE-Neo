# R85：当前F0与strong-rec完整CPU流水线成本

2026-11-17；Codex  (sqs_A100)。事前登记，不训练新模型、不扩大已止损配置。依据论文RESEARCH_STATUS中的成本缺口与note68。仅测已完成质量/感知评价的两seed R44 square_mse原4075参数F0，以及自身raw half-FB/warp/recursive .5；这是必要基线测量，不是新方法、质量重算或手机实验。

## 固定范围与预算

原R30六SYN条件（3源、480×854）及R10四native_crop ND（288×512）全部保留，两模型seed分别报告。每条件只处理原前16帧，不resize/pad/挑片；旧输入cache读取/来源校验、模型加载、参考预测读取均在计时外。原npz可能解码整段low，不能称只读了16帧；无新数据源、最终像素、GT指标或增强权重。以当前模型重新实际执行CNN，不复用raw缓存绕过部署骨干。

每个seed-条件：两次整段warmup/模式，随后三次整段测量/模式；每轮两模式顺序按(轮次+seed)奇偶交替，场景顺序沿原index。每次16帧均从空历史开始，首帧算入总成本。两模式×两seed×十条件×五轮×16帧=3200实际B1骨干前向（warmup1280、正式1920）；strong-rec共100次序列、每次15对，合1500 half-FB调用/3000 Farneback。保存80 warmup、120正式逐序列行及全部逐帧时延，不以最快重复报告结果，无墙钟截止/科学自动重试。

每seed-条件第一轮warmup两模式的完整16帧输出，分别对同seed原已完成raw/recursive缓存前16帧核最大绝对差≤1e-5（归一化[0,1]单位）；共40资格记录，直接复用本warmup、不增加CNN。任何数值/有限性/来源失败保留并停，不更改精度、输入或容差追分。不将此有限数据等价视为所有输入的逐bit证明。

## 计时及内存语义

CPU FP32、Torch2/OpenCV1、确定性、inference_mode，无CUDA/TF32/新SGD。完整单帧路径包含HWC float[0,255]至BCHW float/255、实际原CNN、clip/输出转HWC×255、可选half-FB（依赖上一raw与当前raw）、实际上一fused native warp与mask fallback/.5融合，以及向预分配CPU输出sink复制。时间从首帧转换前至末帧sink复制后，全部Python调度与逐帧计时开销也在序列wall内。记录input+CNN+output转换、motion+warp+blend、sink copy三个分段，但以完整wall/16为主，不以分段计时替代完整路径。

解码/模型加载、输出sink分配、保存JSON、参考比较均在区间外；不包含相机/文件I/O、display、JOD、服务排队或手机transfer。sink只是两模式相同的宿主输出缓冲，容量独立报告，不冒充方法持久状态。raw无时间状态；rec保留上一raw与fused两FP32 RGB（稳定状态6HW×4B），记录实际storage并区分首帧两者共享存储。flow/当前图/临时workspace与CNN激活不计入这个状态数，不能称完整RSS/手机峰值。

记录CPU型号、可用亲和CPU数、Torch/OpenCV版本/线程、host load起止、参数数、每次序列/逐帧和进程CPU时间。共享服务器CPU非独占，测量分布是描述性数据，不把差异因果归给网络或当手机性能。此次CPU实验不需占GPU，也不使用GPU空闲读数作为CUDA准入。

## 汇总与使用

每seed-条件报告三次完整ms/frame的中位数/最小/最大、对应rec/raw中位数比、首帧与非首帧分布、每模式状态/sink字节；再每域每seed等条件平均（同时保留源分布），不合并不同尺寸与两个seed挑最好。延迟倒数仅本循环的平均吞吐，不能声称流式相机端到端延迟/手机FPS或p95可靠统计。样本数仅三次，不给虚假置信区间。

没有成本优劣通过门槛或调参救分，完整测量正常才进入论文证据入口；不把时间量当新方法资格、不加入R84训练窗质量、不为已失败R82/R74配置补测。若完成，当前共同DEV质量表仍源自原完整序列，成本是相同源/分辨率/权重前16帧的独立测量，必须披露这一不同，不能说两者逐帧完全对应。
