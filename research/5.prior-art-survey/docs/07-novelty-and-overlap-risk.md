# 新颖性与重复风险分析

- 创建：2026-11-05 · claude code (local)
- 输入：`02-mobileie-citations.md`、`03-direct-followups.md`、`04-teleai-and-industry.md`、`05-video-temporal-survey.md`、`06-lightweight-deployment.md`
- 目的：把“能发什么”与“会被指重复什么”写清楚，指导后续实验与写作。

## 1. 已确认的空白

1. **没有 MobileIE（4K 参数、单图增强）的视频/时序扩展**：公开引用中无直接工作；
2. **没有“极轻量单图增强网络 + 训练期时序约束 + 推理零开销”的组合**：Zero-DCE 视频版有训练期损失，但不是 4K 参数 CNN，也未处理局部高频噪声放大；
3. **没有“可见性驱动的时序损失”用于增强模型闪烁**：JND/平坦区加权在编码/去闪烁中出现，但未用于 MobileIE 类模型；
4. **没有“MobileIE 量化后的时序稳定性”研究**：TAQ/QBasicVSR 针对视频超分，未覆盖 4K 参数 RGB 低光增强；
5. **缺少手机真实夜景视频上的系统评测**：多数工作停留在 GPU/合成视频。

## 2. 候选贡献（按推荐优先级）

### C1（主贡献）：面向极轻量单图增强网络的训练期时序一致性

- **做什么**：在 MobileIE 训练中加入对齐后的时序一致性损失（flow warp + 遮挡 mask），推理图完全不变；
- **为什么不是重复**：Zero-DCE 视频版是曲线模型；JFFRA 是重视频复原网络；没有工作把它用于 4K 参数 CNN，并解释“网络放大了哪些噪声”；
- **需要实验**：合成 + 真实视频；闪烁、PSNR/SSIM、参数/MACs/延迟；与 EMA/光流 EMA 同延迟对比；快速运动。
- **证据强度要求**：闪烁降 ≥50%，PSNR 降 ≤0.1 dB，快速运动仍有效。

### C2（差异化）：可见性加权的时序损失（JND / 平坦区 / 频谱）

- **做什么**：不把所有像素一视同仁，而是对“人眼更容易察觉的闪烁”加权：
  - 平坦区域权重更高（3 号工作发现平坦区与纹理区残差相当，但平坦区更显眼）；
  - JND 阈值附近的差异加权；
  - 时间高频段（>3 Hz）加权（3 号工作发现输出噪声 80% 功率在高频）。
- **为什么不是重复**：JND 用于编码/预滤波（#29），未用于“增强模型引入的闪烁”；
- **需要实验**：加权 vs 不加权的消融；主观盲评；不同场景（平坦天空/纹理）。
- **风险**：需要证明权重不是“调参魔法”，而是有 3 号工作的测量依据。

### C3（部署真实性）：量化感知的时序稳定性

- **做什么**：MobileIE slim → ONNX → INT8/TFLite，测量量化前后闪烁；若量化放大闪烁，设计时序感知的量化校准/损失；
- **为什么不是重复**：TAQ/QBasicVSR 是视频超分；没有 4K 参数 RGB 低光增强的量化闪烁研究；
- **需要实验**：FP32 vs INT8 的闪烁、PSNR、延迟；不同量化方案（PTQ/QAT）；手机实测。
- **价值**：把“能上手机”从口号变成可测量结果；也可作为论文的第二贡献。
- **风险**：若量化影响很小，则降级为实验章节，不单独作为贡献。

### C4（分析贡献）：闪烁来源的逐模块消融

- **做什么**：训练期移除全局/局部注意力、FST、MBR 多分支、warm-up，量化各自对闪烁与画质的影响；
- **为什么有价值**：3 号只做了“冻结全局注意力”，导师明确要求逐模块理解；审稿人也会问“为什么是时序损失而不是改结构”；
- **需要实验**：4 号工作的 `ablation-plan.md`；
- **定位**：支撑 C1/C2 的机理分析，不单独作为主贡献。

## 3. 重复风险矩阵

| 对比对象 | 重叠点 | 风险 | 差异化话术/实验 |
| --- | --- | --- | --- |
| Zero-DCE 视频版 | 训练期曝光/颜色一致性损失、推理零开销 | **高** | 4K 参数 CNN；局部高频噪声放大；JND/平坦区加权；重参数化兼容；手机实测 |
| JFFRA / StableLLVE | 光流对齐 + 时序损失 | 中 | 轻量级/零推理开销；MobileIE 结构性消融 |
| YUV / LiteIE / FGDPA / DRNet（同组） | 轻量、重参数化、低光/水下 | **中高** | 它们是单图；我们解决帧间一致性；不声称结构/效率首次 |
| AnyMod-LLVE / UbiEnlight | 视频低光增强、时序一致性 | 中 | 模型量级不同；我们不做 SOTA 画质，主打 4K 参数/实时 |
| EMA / 光流 EMA / BlazeBVD | 去闪烁后处理 | **高** | 快速运动、无拖影、无额外延迟；同延迟对比；真实视频 |
| TAQ / QBasicVSR | 量化 + 时序一致性 | 中 | 任务不同（VSR vs RGB LLIE）；模型量级不同；可作为 C3 的对照/引用 |
| Mobile AR 论文（#10） | 在视频管线中使用 MobileIE | 低 | 它做 vSLAM 自适应触发，不建模闪烁；可作为“应用需求”引用 |
| 导师提到的 TeleAI 工作 | 未知 | 待定 | 未证实；拿到出处后再评估 |

## 4. 审稿人可能的质疑与准备

| 质疑 | 准备 |
| --- | --- |
| “时序一致性损失是现成的，创新不足” | 用 C2（可见性加权）+ C4（模块消融）证明不是套用；强调零推理开销与 4K 参数约束；给出手机实测 |
| “后处理 EMA 就够了” | 快速运动/遮挡/延迟边界实验；同延迟对比；展示后处理的拖影 |
| “只在合成视频上验证” | 真实手机夜景视频 + 公开数据集；合成/真实分别报告 |
| “画质下降换闪烁，不值得” | PSNR/SSIM 约束；闪烁-画质 Pareto 曲线；主观盲评 |
| “为什么不直接用视频模型？” | 手机实时/4K 参数硬约束；视频模型延迟/功耗不可接受 |
| “量化后还能用吗？” | C3 实验；若量化放大闪烁，正好成为贡献 |
| “和 YUV/LiteIE 有什么区别？” | 它们是单图；我们在视频帧间；引用并明确边界 |
| “闪烁指标不统一” | 同时报告对齐残差、时间 std、JND 超限、频谱；公开代码/数据 |

## 5. 论文叙事建议

**推荐主线**：

> *Taming Flicker in Ultra-Lightweight Image Enhancement: Visibility-Aware Temporal Consistency at Zero Inference Cost*

结构：

1. 现象：MobileIE 逐帧处理导致 18/255 闪烁（3 号工作）；
2. 分析：逐模块消融 + 可见性分析，指出放大器与感知关键区域（C4）；
3. 方法：训练期时序损失 + 可见性加权 + 遮挡 mask（C1/C2），推理图不变；
4. 部署：INT8/TFLite 时序稳定性（C3，若结果支持）；
5. 实验：合成 + 真实、快速运动、与后处理同延迟对比、手机实测。

**备选主线**（若 C1 效果不足）：

> 轻量后处理 + 训练约束的组合；或转向“量化感知时序稳定性”作为主贡献。

## 6. Go / No-Go 判据

| 阶段 | 判据 | 不满足时的动作 |
| --- | --- | --- |
| 方案 A 首次训练 | 闪烁降 ≥30%，PSNR 降 ≤0.2 dB | 调 λ / 换损失；仍不行则加轻量模块 |
| 完整方案 | 闪烁降 ≥50%，PSNR 降 ≤0.1 dB | 降级为“分析 + 后处理组合”论文 |
| 快速运动 | 16 px/帧下仍降 ≥30%，无拖影 | 引入遮挡 mask / 鲁棒损失 |
| 量化 | INT8 闪烁不显著恶化，或可被时序校准修复 | 若严重恶化且无法修复，C3 作为负面发现/未来工作 |
| 真实视频 | 相对 EMA/光流 EMA 不劣，快速运动更优 | 重新评估选题或缩小场景 |

## 7. 写作中必须避免的表述

- ❌ “首次轻量低光增强/首次重参数化”——已被同组占位；
- ❌ “首次视频低光增强”——AnyMod-LLVE/UbiEnlight 等已做；
- ❌ “后处理一定不够”——必须用实验证明边界；
- ❌ “TeleAI 还没做”——无法证实，改为“公开文献中未发现”；
- ❌ “我们的画质 SOTA”——4K 参数模型不应与重模型比画质，主打效率-一致性权衡。
