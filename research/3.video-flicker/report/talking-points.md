# 今晚汇报要点（3 分钟版）

> 配合 `meeting-brief.html` 使用，按"结论 → 证据 → 问题"顺序讲。

## 1. 复现（30 秒）

- 官方代码与权重在本机完整跑通：LOLv1 eval15 **PSNR 23.633**（论文 23.62），SSIM 0.815，权重 0 缺失；
- 参数量 4,047、0.924 GMACs 与论文一致 → **基线可信，后续实验都建立在这个基础上**。

## 2. 闪烁（60 秒）

- MobileIE 是逐帧单图模型，没有任何时序建模；构造了一段已知运动的合成夜景视频（真实退化：暗部噪声 + JPEG 压缩）；
- 用"已知平移对齐后相邻帧差异"量化：
  - 输入：3.27 / 255
  - 输出：**18.1 / 255（约 7%）**，放大 **5.5 倍**；
- 展示局部放大图与视频（输入/输出对比、帧差放大 20 倍）——**闪烁在贴近真实的条件下可量化、可见**。

## 3. 机制（45 秒）

- 冻结 HDPA 全局注意力后，闪烁没有改善（18.19 vs 18.07），只是整体亮度漂移变小（1.29→0.56）；
- 结论：**主要矛盾不是全局池化，而是局部高频噪声的逐帧随机传播被网络放大**；
- 这决定了后续方向：对"局部细节的时域稳定性"做约束，而不是只改全局注意力。

## 4. 需要老师确认（30 秒）

1. 是否有他看到的闪烁视频/录屏？（最关键，用来对照现象）
2. 闪烁是整体明暗脉动还是局部噪点抖动？拍摄时曝光是否固定？
3. 现象来自开源权重还是他们自己训练的模型？
4. 怎样算"解决"（指标或主观判据）？
5. 4K 参数与手机实时是否硬约束？能否引入跨帧状态？
6. 任务范围（LLE/UIE/ISP）与训练资源。

## 5. 下一步（15 秒）

- 真实夜景视频验证 → 拆解噪声/压缩/曝光贡献 → 做 EMA/光流等 training-free 对照 → 再谈训练侧时序约束。
