# 0031｜FST非线性与插值交换误差诊断

创建：2026-11-11T22:35:31.661797+08:00；作者：Codex  (sqs_A100)；原因：等待R21全评价期间深化原模型算子机制，核查局部二阶矩如何影响RGB，不增加训练模块网格。

固定FST与双线性gather存在可测的交换误差，body局部替换在本轮固定帧上传播到较大RGB差。该结果提供结构研究问题，但尚不证明修正有益、导致R20质量差或具有创新。

## 定义、范围和完整性

对于q(u)=a*u²+b、归一化gather W，Wq(u)-q(Wu)=a*[W(u²)-(Wu)²]。右项是插值邻域二阶中心矩，不是时间噪声方差，也不是运动真值误差。head/body两处局部介入分别续行原网络，不相加解释全网误差；卷积、PReLU、门控和全局上下文也可能不交换。该恒等式本身是直接代数，不称新方法。

官方及R14 native plain双seed4000三权重、四已探索native片段固定7→8帧，12组合×两层=24行。只用同缓存half flow/FBmask，拒绝像素回退当前feature。FP64同OpenCV双线性/BORDER_REPLICATE验证，随机小数平移和整数零差两个fixture通过。恒等式scaled最大残差4.18e-16（预设<=1e-10）；正常stage续行与CPU原forward最大差0（预设<=1e-6）。全部权重/缓存SHA核验，未比较GT质量，不读取最终保留素材。

全四帧均保留，不挑明显例子。body差异传播不等于body造成真实闪烁的占比；不同stage单位和下游敏感性不同，局部RMS不可直接横向归因。合成静态R19、动态R20和本轮单对feature诊断各回答不同问题，不能拼成视频方法已成立的证据。

## 成本与接续

CPU两Torch线程/OpenCV1线程10.707秒，峰值RSS约1.11GiB，CUDA未初始化。PNG/PDF图已查看，表/完整24行/fixture/续行重放/源码与权重清单分别提交。feature状态12通道比RGB贵，两个矩的warp也不比直接warp后FST便宜，不能称效率创新。

优先完成R21全部5888候选评价及2208同CPU参考，判断聚合分布训练能否得到独立历史贡献、是否超越经典强后处理。之后才决定是否在局部统计结构、历史监督或对应可靠性上推进有可证伪目标的下一轮；不据本诊断扩大盲目模块搜索。论文目标持续active。
