# 版本管理规范

## 1. 提交频率

提交应尽可能频繁，达到文件级甚至模块级，即每修改一个文件/模块即做一次提交。

## 2. 提交信息

提交信息可简化，遇到连续提交时，甚至可以使用时间戳占位。

## 3. 提交方式与作者信息

- 使用 SSH 提交。
- 作者信息应标注为 “claude code (local)” 或 “Codex (local)”（取决于执行提交的模型及其所处环境）。
- 默认作者应设置为 `spinner-bot`，且提交仍归属于 GitHub 账号 `spinner-bot`（使用其邮箱），从而方便管理。

本服务器主线按用户明确约定使用作者 `Codex  (sqs_A100)`（两个空格），该约定覆盖上述本地默认署名；移动演示支线由 claude code (local) 负责。

## 4. 合并策略

永久禁用 fast-forward 方式拉取或 merge。所有 `pull` 和 `merge` 操作必须使用 `--no-ff` 参数，确保保留完整的合并历史记录。


## 5. 阶段性推送

继续按文件或模块小步密集提交，不积压已完成改动。每完成一个阶段性工作，向项目远端推送一次；推送不必与每次提交同步。运行中的实验日志只在检查点保留已核验前缀/元数据，完整结束后单独提交，不把未完成输出标作最终结果。推送前检查远端分歧；如需合并，明确使用 `--no-ff`，保留所有小步提交，不以 squash、rebase 或强推压平历史。
